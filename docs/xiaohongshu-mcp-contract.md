# xiaohongshu-mcp sidecar 契约与版本固定（任务 6.3）

## 定位

`xpzouying/xiaohongshu-mcp` 是隔离运行的浏览器自动化辅助进程（sidecar）。
本项目使用标准 Streamable HTTP MCP 客户端连接 `/mcp`，不自行构造
`{tool, args}` HTTP 请求，也不接触页面细节。

## 版本固定（上线前必须完成）

| 项                 | 值                                         | 状态                |
| ------------------ | ------------------------------------------ | ------------------- |
| 选定实现           | `xiaohongshu-mcp`（浏览器自动化 MCP 服务） | ✅ 已选定           |
| MCP 镜像引用       | `${XHS_MCP_IMAGE_REPOSITORY}`（可选）      | ✅ 默认使用上游镜像 |
| 已验证平台策略版本 | `xhs-policy@2026.09`（默认值，实测后修订） | ✅ 初版             |

> 记录规则：一旦在测试账号完成「扫码授权 → 预览 → 发布 → 人工核验」
> 验证，即将实际镜像引用填入上表并记录；
> 任何升级都需要重新运行适配器契约冒烟测试（`tests/worker/publisher.test.ts`）。

## 适配器契约（本项目调用的 MCP 工具）

| MCP 工具             | 入参                                          | 出参                 | 对应契约操作 |
| -------------------- | --------------------------------------------- | -------------------- | ------------ |
| `check_login_status` | 空对象                                        | 已登录或未登录的文本 | `checkAuth`  |
| `publish_content`    | `title`, `content`, `images[]`, 可选 `tags[]` | 发布成功/失败的文本  | `publish`    |

- `validate` / `preview` 在适配器内本地实现（无外部副作用，不调用 sidecar）。
- `images[]` 使用内容中心按 `fileId` 获取的最新 CDN URL；该 URL 必须能被 MCP 容器访问。
- 登录 Cookie 保存在 MCP 容器数据卷中，本项目调用工具时不传账号 Cookie。
- 管理台已接入 `get_login_qrcode`，点击概览页登录账号模块即可扫码登录，并通过
  `check_login_status` 串行轮询结果；`delete_cookies` 保留给后续账号切换流程。
- 上游没有发布结果中的笔记 ID，也没有按 ID 核验发布的工具。因此适配器不会伪造回执或自动标记 `SUCCEEDED`；收到成功文本后任务进入 `NEEDS_HUMAN`，由运营核对实际结果。当前后台尚无将此状态人工改为已发布/未发布的操作，接入实发前须补齐。

## 错误分类映射

| sidecar 表现                      | 分类            | 处置                     |
| --------------------------------- | --------------- | ------------------------ |
| 登录检查连接失败                  | `TRANSIENT`     | 有界退避重试             |
| 发布调用超时、传输异常或工具报错  | `NEEDS_HUMAN`   | 不盲发，人工检查实际结果 |
| 未登录                            | `AUTH_REQUIRED` | 扫码登录后再检查         |
| 登录状态响应不可解析              | `SELECTOR`      | 检查上游版本与适配器契约 |
| 发布成功文本但没有可核验的笔记 ID | `NEEDS_HUMAN`   | 人工确认已发布或未发布   |

## 熔断与恢复

- 同一账号连续 3 次 `SELECTOR` 错误 → 打开熔断器（30 分钟），期间该账号
  发布任务全部进入 `NEEDS_HUMAN` 并提示运营人员。
- 恢复方式：人工修复（升级 sidecar / 修正契约）后，运行适配器契约
  冒烟测试通过即自动关闭熔断器。

## 运行方式

本地开发可用根目录 `docker-compose.yml` 启动 sidecar。宿主机 API 和 Worker 设置
`XHS_MCP_URL=http://127.0.0.1:18060/mcp`；如果应用也在 Compose 网络中运行，
则使用 `http://xiaohongshu-mcp:18060/mcp`。两进程还必须设置
`XHS_MCP_ACCOUNT_ID`（本平台当前绑定的账号 UUID）。
任一缺失时发布 Worker 不启动；其他账号不能使用该实例检查授权或发布。
该绑定只限制本平台的账号 ID；上游登录检查返回展示用户名而非稳定账号 ID，
上线前仍须人工确认容器实际登录的是所绑定账号，切换账号后也须重新核对。
如在 MCP 前设置了鉴权代理，配置
`XHS_MCP_AUTH_TOKEN_REF=env:XHS_MCP_AUTH_TOKEN`，并在两进程注入对应令牌。
上游容器只有一份当前登录态；在账号切换和发布任务互斥机制完成前，
不要将多个平台账号接入同一实例。生产环境使用部署配置中的镜像引用；本地
Compose 默认沿用上游镜像引用。任何镜像引用变更都需要重新运行适配器契约冒烟测试。

镜像引用记录在 `docs/xiaohongshu-mcp.lock.json`，真实值由部署环境提供。
