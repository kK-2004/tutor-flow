## ADDED Requirements

### Requirement: 提供与原型一致的应用框架

系统必须（SHALL）提供中文管理后台，其中包含固定侧栏导航、顶部上下文/搜索/操作区，以及概览、工作流、工作流详情、草稿箱、草稿编辑、研究资料、发布管理和系统设置视图。

#### Scenario: 运营人员在视图之间导航

- **WHEN** 运营人员选择导航项或打开资源
- **THEN** 系统展示对应视图和面包屑，URL 可以直接导航，并且不会丢失服务端业务状态

#### Scenario: 展示平台选择控件

- **WHEN** 管理后台渲染创建、筛选、设置、预览或发布控件
- **THEN** 系统只提供小红书作为目标平台，不显示后续平台的控件

### Requirement: 展示运营概览

系统必须（SHALL）展示由服务端数据计算的执行中任务、待审核草稿、排队中或失败的发布、搜索用量、模型 Token 用量和最近活动。

#### Scenario: 加载概览页

- **WHEN** 运营人员打开概览页
- **THEN** 管理后台展示当前指标、最近运行任务、状态和数据更新时间，且不依赖预置或随机演示数据

### Requirement: 操作并检查工作流

系统必须（SHALL）允许运营人员搜索和筛选运行任务，并检查任务的主题、模式、账号、状态、步骤、尝试、事件、用量、候选方向、错误和可执行操作。

#### Scenario: 等待人工选择方向

- **WHEN** 运营人员打开状态为 `WAITING_DIRECTION` 的运行任务
- **THEN** 管理后台展示结构化方向卡片，并提供一次有效的选择操作

#### Scenario: 运行任务出现已分类错误

- **WHEN** 运行任务或步骤失败
- **THEN** 管理后台展示错误分类和安全的下一步操作，并且只在允许时显示重试或人工处理控件

### Requirement: 管理草稿箱和编辑器

系统必须（SHALL）提供待审核草稿统计、搜索、状态筛选、草稿打开、保存状态、校验反馈、修订冲突处理，以及小红书预览和批准操作。

#### Scenario: 运营人员编辑草稿

- **WHEN** 运营人员修改草稿内容
- **THEN** 管理后台展示未保存、保存中、已保存或存在冲突的状态，并预览已持久化的实际生效内容

#### Scenario: 草稿审核通过

- **WHEN** 批准操作成功
- **THEN** 草稿离开待审核草稿箱，并且管理后台导航到或提供链接指向新创建的发布任务

### Requirement: 展示研究来源链路

系统必须（SHALL）展示运行任务抓取的来源，包括来源类型、标题、域名、语言、评分、重复状态、抓取状态，以及引用每项来源的事实。

#### Scenario: 运营人员检查研究来源

- **WHEN** 运营人员选择一个研究来源
- **THEN** 管理后台展示其归一化元数据和事实使用位置，并且不执行或信任来源页面中的内容

### Requirement: 管理小红书发布任务

系统必须（SHALL）展示排队中、发布中、已成功、已失败、结果未知和需要人工处理的任务，以及账号别名、尝试次数、内容版本、平台标识或 URL、核验状态、时间戳和可执行操作。

#### Scenario: 发布任务需要人工处理

- **WHEN** 任务因授权、验证、策略或未知结果而被阻塞
- **THEN** 管理后台将其与可重试失败清晰区分，并展示所需的解决操作

### Requirement: 配置非敏感系统行为

系统必须（SHALL）提供模型别名、搜索查询次数和预算、质量门槛、生效的小红书策略引用、默认审核模式和外部调度接口文档等设置，同时不得暴露密钥值。

#### Scenario: 运营人员打开系统设置

- **WHEN** 系统设置加载完成
- **THEN** 管理后台展示已持久化的非敏感配置和连接健康状态，而密钥字段不存在或只展示已配置/未配置状态

#### Scenario: 运营人员保存无效设置

- **WHEN** 某个值超出允许范围，或会关闭强制安全门槛
- **THEN** 管理后台展示校验错误，并且服务端保留之前的配置

### Requirement: 支持浅色、深色和跟随系统主题

系统必须（SHALL）支持浅色、深色和跟随系统主题，并且可以（MAY）在本地保存这一非敏感偏好。

#### Scenario: 系统主题发生变化

- **WHEN** 当前选择跟随系统，并且操作系统颜色方案发生变化
- **THEN** 管理后台无需重新加载即可更新主题，且不改变任何业务数据

### Requirement: 使用图标字体库并禁止 Emoji 和 SVG

管理后台必须（MUST）使用已安装的 CSS/Webfont 图标库提供界面图标，并且不得（MUST NOT）在用户界面中使用 Emoji、内联 SVG、外部 SVG 文件、SVG 图标组件或程序生成的 SVG。

#### Scenario: 渲染带图标的控件

- **WHEN** 导航项、状态控件、工具栏操作或按钮需要图标
- **THEN** 控件使用已批准的 Webfont 图标类，并保留可见文字或无障碍名称

#### Scenario: 执行前端质量检查

- **WHEN** Lint 或构建校验扫描应用界面源码
- **THEN** 检查在发现禁止的 SVG 资源/组件或作为界面装饰的硬编码 Emoji 时失败

### Requirement: 满足响应式和基础无障碍要求

系统必须（SHALL）支持键盘操作、可见焦点、语义化标签、不只依赖颜色表达状态、可读对比度，以及可在桌面和窄屏使用的布局。

#### Scenario: 纯键盘用户操作模态框

- **WHEN** 纯键盘用户打开新建任务模态框
- **THEN** 焦点进入模态框，在关闭前保持在其中，并在关闭后返回触发控件

#### Scenario: 屏幕阅读器读取纯图标操作

- **WHEN** 屏幕阅读器遇到纯图标控件
- **THEN** 控件具有本地化的无障碍名称，并且装饰性图标对辅助技术隐藏
