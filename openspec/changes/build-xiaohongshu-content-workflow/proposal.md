## 变更原因

当前原型已经验证了“研究、选题、生成、审核、发布”的产品闭环，但仍是依赖 `localStorage` 和定时器模拟的单页演示，无法被定时器可靠触发，也无法安全处理长流程恢复、事实溯源、人工停点、发布幂等和小红书登录失效。现在需要将研究结论与页面原型固化为一套可实施的首期规格，在控制平台自动化风险的前提下，先交付小红书单平台的完整生产闭环。

## 变更内容

- 将离线原型升级为持久化的内容工作台，覆盖概览、工作流列表与详情、草稿箱、草稿编辑、研究资料、发布管理和系统设置。
- 提供手工创建和外部定时器触发入口，以幂等键创建可恢复工作流；支持实时进度、人工选方向、重试和取消。
- 建立“检索资料 → 去重与评分 → 事实/来源绑定 → 结构化方向推荐 → 核心文章 → 小红书版本”的内容生产链路。
- 支持自动选择或人工选择内容方向，以及自动发布或人工审核两种运行策略；低质量或高风险内容必须转人工处理。
- 将人工审核内容送入草稿箱，支持编辑、自动保存、平台预览、规则校验和批准发布。
- 首期只提供小红书账号连接、平台规则、发布队列、幂等回执、失败分类与人工恢复；不实现知乎、微信公众号、微博、B 站等平台。
- 保存来源、模型、提示词版本、人工审核和 AIGC 标识状态等审计数据，并将密钥、Cookie 与业务数据隔离。
- 前端不得使用 emoji 或 SVG；所有功能图标统一来自可访问的图标库，并提供文本或 `aria-label`。

## 能力范围

### 新增能力

- `workflow-orchestration`: 内容任务的手工/外部定时触发、幂等创建、可恢复状态机、实时事件、人工选方向、重试与取消。
- `research-provenance`: 检索计划、网页资料归一化与去重、来源评分、事实引用绑定以及结构化方向推荐。
- `content-review`: 核心文章和小红书衍生稿生成、草稿箱、编辑与自动保存、预览、审核门禁和 AIGC/内容合规校验。
- `xiaohongshu-publishing`: 小红书账号授权状态、版本化平台规则、发布队列、隔离发布适配器、幂等回执、验证和失败恢复。
- `operations-console`: 与原型一致的管理后台信息架构、筛选统计、系统配置、主题切换、响应式与无障碍图标约束。

### 变更能力

无。当前项目不存在既有 OpenSpec 能力规格。

## 影响范围

- 新增 Next.js/TypeScript 管理后台和服务端 API，并将长流程执行拆分到独立编排及 Worker 边界。
- 新增 PostgreSQL 持久化；低规模首期使用 Redis/BullMQ 承载队列、重试、限流和定时作业，保留迁移到 Temporal 的领域边界。
- 接入可配置的搜索与 LLM 网关、对象存储，以及优先基于 `xiaohongshu-mcp` 的隔离 Publisher Adapter。
- 对外提供内容任务、执行、方向选择、草稿、发布任务、设置、SSE 事件流和外部调度接口。
- 运维面新增密钥托管、账号级串行/限流、审计日志、结构化日志与执行指标；浏览器发布故障不得拖垮 API 或内容生产流程。
